Lesson 06

Files, Paths, Streams, and Lazy Work

Separating filesystem locations from open handles, then processing data incrementally

The Big Picture

For a file-processing tool, three ideas are easy to blur together: where a file is, the open object used to access it, and the current position within that access stream. Python's pathlib makes locations expressive; file objects represent active access; iterators and generators let the tool consume records without loading everything at once.

┌─────────────────────┐ open() ┌─────────────────────────────┐ │ Path │ ─────────→ │ file object / stream │ │ "assets/take.fbx" │ │ mode, encoding, cursor │ └─────────────────────┘ └──────────────┬──────────────┘ │ read / iterate ▼ bytes or decoded text records
🧠 Key Concept: A path is not a file pointer

A Path is a value describing a filesystem location. An open file object is a live resource with a mode, buffering behavior, and cursor. You can have a path without opening anything, and one path can be opened by multiple independent streams.

Paths with pathlib

from pathlib import Path

root = Path("assets")
for source in root.rglob("*.fbx"):
    output = source.with_suffix(".gltf")
    print(source, "->", output)

manifest = root / "manifest.json"
print(manifest.exists())

Path operations construct and inspect locations without opening files. The / operator joins path components in a platform-aware way. glob and rglob find paths; they do not read file contents. This is analogous to using System.IO.Path and directory enumeration in C#, but Path is an object with convenient methods rather than a collection of static string helpers.

⚠️ Python Surprise: A path string does not read anything

Path("asset.fbx") does not prove that the file exists, open it, or reserve a handle. Use path queries for filesystem metadata and open() when you need a stream.

File Objects, Modes, Cursors, and Buffering

Opening a path creates a file object. Text mode decodes bytes into strings using an encoding; binary mode returns bytes. Common modes include "r" for reading, "w" for truncating and writing, and "a" for appending. Be explicit about encoding for text files.

from pathlib import Path

with Path("manifest.txt").open("r", encoding="utf-8") as stream:
    first_line = stream.readline()
    position_after_line = stream.tell()
    stream.seek(0)
    all_text = stream.read()

with Path("texture.bin").open("rb") as binary_stream:
    header = binary_stream.read(16)

The cursor is the stream's current read or write position. readline advances it; tell reports a position; seek moves it. Buffering may mean Python reads a larger chunk from the operating system than the exact characters requested, but the file object's interface still presents a logical cursor. A C# comparison is FileStream.Position plus a reader or writer layered over the stream.

The with statement closes the resource at the end of the block, including when an exception escapes. It is the correct default for files. A path can be retained for later work; a file object should not be used after its context has closed it.

💡 Important: Keep resource lifetime local

Pass a Path when a function needs a location. Open a file inside the smallest scope that needs the stream, and let with own cleanup. This avoids handing a closed or accidentally shared cursor to another stage.

Iterables, Iterators, and Generators

An iterable can produce values for a for loop. An iterator is the stateful object that provides the next value and eventually raises StopIteration. A generator function uses yield to produce one value, suspend, and resume later:

def nonempty_lines(path: Path):
    with path.open(encoding="utf-8") as stream:
        for line in stream:
            cleaned = line.strip()
            if cleaned:
                yield cleaned

for line in nonempty_lines(Path("events.log")):
    print(line)

Calling nonempty_lines does not read the file immediately; it returns a generator. Each loop step resumes execution until the next yield. This is similar to C# IEnumerable<T> with yield return, though Python's generator object is directly an iterator.

┌──────────────┐ next() ┌─────────────────────┐ yield ┌──────────┐ │ caller loop │ ─────────→ │ generator suspended │ ───────→ │ one item │ └──────────────┘ └──────────┬──────────┘ └────┬─────┘ │ resume │ └───────────────────────────┘ stop early: no later records read

Lazy iteration is valuable for large logs or directory scans. It reduces peak memory and can stop as soon as a match is found:

match = next((line for line in nonempty_lines(Path("events.log"))
              if "ERROR" in line), None)

This does not make every operation faster; repeated disk access, expensive parsing, or a consumer that eventually needs every item can dominate. The benefit is deferred work, early exit, and bounded memory.

JSON and CSV Records

JSON maps naturally to Python dictionaries, lists, strings, numbers, booleans, and None. CSV is tabular text, so csv.DictReader presents each row as a dictionary whose values are strings until you convert them:

import csv
import json

with Path("config.json").open(encoding="utf-8") as stream:
    config = json.load(stream)

with Path("assets.csv").open(newline="", encoding="utf-8") as stream:
    rows = csv.DictReader(stream)
    for row in rows:
        width = int(row["width"])
        print(row["path"], width)

Do not assume that external JSON or CSV is valid, complete, or typed exactly as your model expects. Parsing is separate from validation. A technical-art importer should report which path or row failed rather than allowing a vague conversion error to appear many stages later.

💚 Technical-Art Relevance

Use paths for asset discovery, streams for controlled access, generators for large manifests, and JSON/CSV parsers at interchange boundaries. This separation lets a batch tool scan millions of records without loading every line or confusing a filename with an open handle.

Short Drills

  2. Build a generator that yields only files larger than a chosen byte count, and stop after the first match.
  3. Read a CSV row and explicitly convert one numeric field. Explain why the CSV reader does not do that conversion for you.

Key Takeaways

  • Path: a location value; it is not an open resource or cursor.
  • File object: a live text or binary stream with mode, buffering, and position.
  • With: owns cleanup for the stream's lifetime.
  • Generator: yields values incrementally, enabling lazy scans and early exit.
  • Structured data: JSON and CSV parsing produce data that still requires validation.
