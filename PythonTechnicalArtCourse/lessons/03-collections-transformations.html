Lesson 03

Collections and Pythonic Data Transformations

Lists, records, sets, and readable transformations compared with C# LINQ

The Big Picture

Technical-art tools are mostly data plumbing: collect asset paths, group metadata, remove duplicates, select candidates, and produce a new representation. Python's collection syntax makes those operations compact, but compact does not mean mysterious. Start by choosing the collection that expresses the data contract, then choose a transformation whose evaluation and mutation behavior you can explain.

┌──────────────────────┐ transform ┌──────────────────────────┐ │ source collection │ ────────────→ │ result collection │ │ paths / records │ │ selected / mapped values │ └──────────┬───────────┘ └────────────┬─────────────┘ │ │ ├─ list: ordered, mutable ├─ comprehension ├─ tuple: fixed grouping ├─ map / filter ├─ dict: key → value └─ explicit loop └─ set: unique membership
🧠 Key Concept: A collection is a contract

Choose a list when order and duplicates matter, a tuple for a fixed grouping, a dictionary for keyed lookup, and a set for uniqueness or membership. The syntax is secondary to the data guarantee.

Literal Syntax and the Core Collection Types

paths = ["hero.fbx", "tree.fbx", "hero.fbx"]  # list
origin = (0.0, 0.0, 0.0)                       # tuple
settings = {"lod": 2, "compressed": True}     # dict
extensions = {"fbx", "gltf", "obj"}           # set
empty_dict = {}                                # not an empty set
empty_set = set()

Square brackets create lists, parentheses create tuples, braces with key-value pairs create dictionaries, and braces with values create sets. An empty pair of braces is a dictionary, so use set() for an empty set. Dictionaries preserve insertion order in current Python implementations, but their primary contract is key lookup; sets intentionally do not provide a stable sequence order for presentation.

💡 Important: Performance follows the operation

“Pythonic” does not mean “free.” A set is a good membership index, but converting a list to a set costs time and loses sequence order. A list comprehension creates a new list; repeated concatenation can copy data. Choose the structure and operation that match the workload.

Mutation, Slicing, and Unpacking

Lists, dictionaries, and sets can be mutated. That is useful for a work queue, but shared references make ownership important:

pending = ["a.fbx", "b.fbx", "c.fbx"]
alias = pending
alias.pop(0)                 # mutates pending too

snapshot = pending.copy()    # shallow copy of the list structure
snapshot.append("d.fbx")     # pending is unchanged

Slicing selects a contiguous range by position and returns a new sequence. It is not filtering by a predicate:

names = ["a.fbx", "b.txt", "c.fbx", "d.png", "e.fbx"]
middle = names[1:4]          # positions 1, 2, 3
last_two = names[-2:]        # positions from the end
reversed_names = names[::-1] # new reversed list

fbx = [name for name in names if name.endswith(".fbx")]  # filtering

Slice syntax is sequence[start:stop:step]; the stop position is excluded. Negative indices count from the end. Filtering asks a question about each element and is normally expressed with a loop, comprehension, or filter.

⚠️ Python Surprise: Slicing is not filtering

items[2:5] selects positions 2 through 4. It does not mean “items matching condition 2 through 5.” Use a predicate-based transformation when the selection depends on content.

Unpacking assigns elements from an iterable to several names at once:

width, height = (1920, 1080)
first, *middle, last = ["a", "b", "c", "d"]
name, metadata = ("tree.fbx", {"lod": 1})

Comprehensions, lambda, map, and filter

A comprehension is a compact loop that builds a collection. Read it as “the output expression for each item, optionally kept when a condition is true.”

records = [
    {"path": path, "extension": path.rsplit(".", 1)[-1]}
    for path in ["hero.fbx", "tree.gltf", "readme.txt"]
    if "." in path
]

unique_extensions = {record["extension"] for record in records}
by_name = {record["path"]: record for record in records}

lambda creates a small anonymous function. map applies a function to each item, and filter keeps items for which a predicate is true. In modern Python these functions return lazy iterators, so materialize them with list() when you need a reusable list.

names = ["tree.fbx", "hero.fbx", "camera.fbx"]
sorted_names = sorted(names, key=lambda name: name.lower())
fbx_names = list(filter(lambda name: name.endswith(".fbx"), names))
lengths = list(map(len, names))

The direct C# LINQ comparison is useful but limited. Select resembles map, Where resembles filter, and OrderBy resembles sorted(..., key=...). Python does not turn every collection into a fluent object with chained methods. Transformations are usually function calls, comprehensions, or generator expressions, and their laziness differs by operation.

💚 Technical-Art Relevance

For an asset manifest, a readable comprehension can normalize extensions, filter temporary files, and build a lookup dictionary. Keep complex validation in a named function or loop when a one-line expression would hide an important pipeline rule.

Short Drills

  1. Given a list of paths, use slicing to take the first three positions, then use a separate predicate to keep only .fbx files. Explain why the operations are different.
  2. Build a dictionary keyed by file extension whose values are unique paths. Decide where a set is useful and where list order must be preserved.
  3. Rewrite a short C# LINQ chain using a Python comprehension, then rewrite it with map/filter. Which version makes the asset rule easiest to audit?

Key Takeaways

  • Collections: list, tuple, dict, and set communicate different guarantees.
  • Slicing: selects positions; filtering selects by a predicate.
  • Transformations: comprehensions, map, and filter create or yield transformed data; they do not automatically mutate the source.
  • LINQ bridge: Python has analogous operations, but not a universal fluent method chain.
