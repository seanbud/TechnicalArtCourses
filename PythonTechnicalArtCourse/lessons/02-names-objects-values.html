Lesson 02

Names, Objects, Values, and Types

The object model behind Python assignment, collections, and classes

The Big Picture

In C#, it is natural to explain a variable as a typed storage location. Python is easier to predict when you start with a different model: objects exist, and names are bindings that refer to objects. Assignment changes a binding; it does not inherently copy a value or permanently attach a type to the name.

┌──────────────┐ binds to ┌────────────────────────┐ │ name: files │ ───────────────────→ │ list object │ └──────────────┘ │ type: list │ │ │ contents: ["a.fbx"] │ │ rebinding └────────────────────────┘ ▼ ▲ ┌──────────────┐ old object unchanged │ │ name: files │ ────────────────────────────────┘ │ now points to│ │ another list │ └──────────────┘
🧠 Key Concept: Names are labels

Think of a name as a label on an object, not a box that owns a value. Multiple names can refer to one object, and a name can later be rebound to an object of another type.

Binding, Rebinding, and Mutation

files = ["hero.fbx"]
alias = files                 # two names, one list
alias.append("tree.fbx")      # mutates that shared list
files = ["camera.fbx"]        # rebinds only the name files

print(alias)                   # ['hero.fbx', 'tree.fbx']
print(files)                   # ['camera.fbx']

Mutation changes an existing object. Rebinding makes a name refer to another object. In C#, a reference-type variable can also refer to a shared object, but Python makes the distinction central and does not require a declaration such as List<string> files before the first assignment.

Immutable objects cannot be changed in place. An operation that appears to modify a string creates a new string and returns it:

label = "hero"
upper = label.upper()     # new string; label remains "hero"
coordinates = (10, 20)    # tuple cannot be changed in place

None, Truthiness, Identity, and Equality

None is Python's singleton value for “no value” or “not present.” It is not the same as an empty string, zero, or an empty collection. Python conditionals also use truthiness: False, None, numeric zero, and empty built-in collections are falsey; most other objects are truthy.

result = find_asset("missing.fbx")
if result is None:
    print("not found")

if not files:
    print("there are no files")

Use == to ask whether two objects compare equal by value. Use is for object identity, most notably value is None. Identity is about whether two references point to the same object; equality is about the objects' comparison result.

💡 Important: Use is None

Do not replace a missing-value check with == None. The identity form communicates the intended singleton check and cannot be customized by an object's equality method.

Dynamic Typing and Type Hints

Python is dynamically typed: the runtime checks whether an operation is valid when the code executes, and a name can be rebound to another type. Type hints document intended use and enable editor support and optional static analyzers, but ordinary Python does not enforce them automatically.

def scale_count(count: int, factor: float) -> float:
    return count * factor

value: str = "lod_0"
# A type checker can flag: value = 3
# Python itself will still execute the assignment.

This is similar to using C# types as a design contract, but without making the annotation the runtime's universal gatekeeper. Built-ins such as int, float, str, list, dict, and bool are objects too, and every object has a type available through type(value).

First Classes: Instances, Attributes, and Methods

A class creates a blueprint-like object that can produce instances. An instance carries per-object state. A method is a function defined on the class; when accessed through an instance, Python supplies that instance as the first argument by conventionally naming it self.

class AssetRecord:
    category = "unclassified"       # class attribute

    def __init__(self, path: str):
        self.path = path              # instance attribute
        self.tags = []                # each instance gets its own list

    def add_tag(self, tag: str) -> None:
        self.tags.append(tag)


record = AssetRecord("assets/tree.fbx")
record.add_tag("environment")
print(record.path)
print(record.category)

AssetRecord("...") creates an instance and calls __init__ to initialize it. record.add_tag("environment") is conceptually like a C# instance call, but the method's self is explicit in the function definition. The class attribute is shared as a lookup default; assigning record.category = "hero" creates an instance attribute that shadows it for that one record.

⚠️ Python Surprise: Never use a mutable class attribute for per-instance state

tags = [] at class scope would create one shared list for every instance. Put mutable per-instance state in __init__, where each object receives a fresh list.

💚 Technical-Art Relevance

Names and mutability explain many pipeline bugs: two tools may unexpectedly share a metadata dictionary, while a copied list may be intentionally independent. Make ownership and mutation visible before parallelizing asset work.

Short Drills

  1. Predict the output of a two-name list example, then run it and explain which line mutates and which line rebinds.
  2. Write a function that distinguishes “missing” (None) from “present but empty” ([]) without using equality to None.
  3. Create two AssetRecord instances, add a tag to one, and verify that the other does not receive it.

Key Takeaways

  • Binding: assignment changes which object a name refers to; mutation changes an object.
  • Mutability: strings and tuples are immutable; lists, dictionaries, and sets are mutable.
  • Checks: use is None for the singleton and == for value equality.
  • Classes: self names the instance, instance attributes hold per-object state, and class attributes are shared defaults.
