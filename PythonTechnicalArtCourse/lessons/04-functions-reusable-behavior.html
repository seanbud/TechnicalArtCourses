Lesson 04

Functions, Calls, and Reusable Behavior

Arguments, callbacks, closures, context managers, and decorators

The Big Picture

A reusable function is a small tool with an input contract and an output behavior. In a technical-art pipeline, one function may normalize a path, another may validate a record, and a third may run an external converter. Python lets you pass those functions around, wrap them, and manage resources with syntax that looks simple but encodes precise behavior.

┌───────────────┐ call arguments ┌──────────────────┐ │ caller │ ─────────────────────→ │ function │ │ values + names│ │ parameters │ └───────────────┘ └────────┬─────────┘ │ return value ←───────────┘ │ function may be passed onward ▼ callback / closure / wrapper
🧠 Key Concept: Behavior is a value

Python functions are objects. You can store a function in a variable, put it in a dictionary, pass it to another function, or return it. This is the bridge from ordinary calls to callbacks, closures, and decorators.

Arguments and Call Shape

Python supports positional arguments, named keyword arguments, defaults, and variable argument groups:

def export_asset(path, output_dir="build", *, compress=False):
    return {
        "path": path,
        "output_dir": output_dir,
        "compress": compress,
    }

export_asset("hero.fbx")
export_asset("hero.fbx", output_dir="web", compress=True)

The * in the parameter list makes compress keyword-only. That can make a tool call self-documenting. A leading *args gathers extra positional arguments into a tuple; **kwargs gathers extra keyword arguments into a dictionary:

def log_steps(label, *steps, **metadata):
    return {"label": label, "steps": steps, "metadata": metadata}

summary = log_steps("export", "validate", "convert", owner="TA")

This resembles C# overloads, optional parameters, and params, but Python resolves one function signature at runtime rather than selecting among multiple overload declarations. Named arguments also make call sites readable, especially for tools with many configuration options.

⚠️ Python Surprise: Default values are evaluated once

Do not use a mutable list or dictionary as a default argument when you expect a fresh value per call. Use None as the sentinel and create the collection inside the function instead.

First-Class Functions, Callbacks, and Closures

Python functions can be passed to a generic operation. The key argument of sorted is a callback: Python calls it for each item to obtain its comparison key.

def extension(path):
    return path.rsplit(".", 1)[-1].lower()

paths = ["TREE.FBX", "hero.gltf", "camera.FBX"]
ordered = sorted(paths, key=extension)

def apply_rule(records, rule):
    return [record for record in records if rule(record)]

A closure is a function that remembers values from the surrounding scope:

def minimum_lod(required):
    def accepts(record):
        return record["lod"] >= required
    return accepts

web_rule = minimum_lod(2)
web_rule({"lod": 3})  # True

The returned function carries the value required with it. C# developers can compare this to a lambda capturing a local variable, but Python's nested function syntax and name lookup are the mechanics to learn. Be mindful of late binding when creating closures inside loops; bind the intended value explicitly rather than assuming each closure receives a snapshot.

Methods, self, and Binding

Lesson 2 introduced self. Here the important connection is that attribute lookup can turn a plain function stored on a class into a bound method:

class Manifest:
    def add(self, path):
        self.paths.append(path)

manifest = Manifest()
manifest.paths = []
manifest.add("tree.fbx")

# Roughly: Manifest.add(manifest, "tree.fbx")

The instance is supplied automatically when you call manifest.add(...); it is explicit as self in the definition. This is related to a C# instance method receiving this, but Python exposes the first parameter in the function signature.

Context Managers and with

A context manager owns a setup-and-cleanup boundary. The with statement enters that context, runs the indented block, and performs the manager's exit behavior even when the block raises an exception.

┌──────────────────────┐ │ enter context │ acquire file, lock, temp resource └──────────┬───────────┘ ▼ ┌──────────────────────┐ │ with-block │ do work; may raise └──────────┬───────────┘ ▼ ┌──────────────────────┐ │ exit context │ close / release / rollback policy └──────────────────────┘ 
from pathlib import Path

with Path("manifest.json").open(encoding="utf-8") as stream:
    text = stream.read()

# stream is closed here, including when reading raises
💡 Important: with is about a lifecycle

with is not an import statement and is not limited to files. It can manage locks, temporary directories, database transactions, network sessions, and custom resources. Imports make names available; context managers control entry and exit around a block.

Decorators and Wrappers

A decorator is a function that receives a function and returns a replacement function, often a wrapper that adds behavior before or after the original call.

from functools import wraps

def announce(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"starting {func.__name__}")
        result = func(*args, **kwargs)
        print(f"finished {func.__name__}")
        return result
    return wrapper

@announce
def build_index(paths):
    return {path: path.rsplit(".", 1)[-1] for path in paths}

The @announce line is equivalent to rebinding build_index = announce(build_index). Wrappers are useful for cross-cutting behavior such as timing, logging, retries, authorization, or consistent tracing. functools.wraps preserves useful metadata such as the wrapped function's name and documentation.

💚 Technical-Art Relevance

Decorators can add timing and structured logging to conversion steps without editing every step. Prefer a normal helper function when the behavior is local, when control flow becomes opaque, or when a wrapper would hide important asset-state changes from the next artist.

Short Drills

  1. Design a function with one required path, one named output option, and one keyword-only safety flag. Call it both positionally and by name.
  2. Write a callback that keeps records above a chosen LOD, then create that callback with a closure.
  3. Use with for a file and explain what cleanup happens. Then name a non-file resource that could use the same lifecycle pattern.
  4. Write a decorator that reports a function's name and returns its result. Decide whether it makes the wrapped tool clearer or more opaque.

Key Takeaways

  • Call shape: positional, named, default, *args, and **kwargs express different contracts.
  • First-class behavior: callbacks and closures let data-driven tools carry rules as values.
  • Binding: instance access supplies self to a method.
  • Lifecycle: with manages setup and cleanup for many resources; it is not an import or file-only feature.
  • Decorators: wrappers add cross-cutting behavior, but should be used only when the abstraction remains visible.
