Headless Automation & APIs

Running ComfyUI as a Headless Background Engine in Corporate Environments

The Big Picture

In a standard creative environment, artists sit in front of the ComfyUI browser tab, dragging wires and clicking the "Queue Prompt" button. In an enterprise-scale game studio like EA, this manual step is a bottleneck. We need to run workflows headlessly—without a UI, triggered automatically by file changes, asset ingestion scripts, or CI/CD pipelines.

Fortunately, ComfyUI was designed from the ground up as a client-server application. The web browser is just a front-end UI. Under the hood, ComfyUI is a Python server that executes tasks based on a JSON graph description. As a Technical Artist, you can export this JSON, bypass the browser, and run workflows programmatically.

🧠 Key Concept: API Format vs. Saved Format

By default, ComfyUI saves workflows in a format that stores node visual layout metadata (coordinates, sizes, colors). The API format strips away all visual fluff, leaving only a lean JSON object containing the node inputs, outputs, and connections. This API JSON is what the Python server executes.

The Headless Execution Pipeline

To run ComfyUI programmatically, the workflow follows a client-server request cycle over HTTP and WebSockets. Here is how an automated script interacts with the ComfyUI backend:

┌─────────────────┐ HTTP POST /prompt ┌─────────────────┐ │ ├───────────────────────────────────────────>│ │ │ │ Sends workflow JSON + Client ID │ │ │ │ │ ComfyUI Server │ │ Python Script │ WebSocket /ws │ (Headless GPU) │ │ (CI/CD Runner) │<───────────────────────────────────────────┤ │ │ │ Receives progress and execution states │ │ │ │ │ │ │ │ HTTP GET /history │ │ │ |<───────────────────────────────────────────┤ │ │ │ Fetches metadata and generated filenames │ │ └─────────────────┘ └─────────────────┘

1. Connect to WebSocket: The script opens a WebSocket connection to receive live progress updates (e.g., sampler steps completed).

2. POST the Prompt: The script sends the JSON workflow to the /prompt endpoint. The server queues the task and returns a unique prompt ID.

3. Listen for Completion: The script monitors the WebSocket for execution messages. When it receives the completion message for the prompt ID, it proceeds.

4. Retrieve Assets: The script requests the final assets from the server using the image names returned in the prompt history.

Python API Script Integration

Here is a production-ready Python script showing how to send an exported API JSON payload to a local or remote ComfyUI instance:

import urllib.request
import json

# Define the server address and prompt payload
server_address = "127.0.0.1:8188"
prompt_workflow = {
    "3": {
        "inputs": {
            "seed": 42,
            "steps": 20,
            "cfg": 7.0,
            "sampler_name": "euler",
            "scheduler": "normal",
            "denoise": 1.0,
            "model": ["4", 0],
            "positive": ["6", 0],
            "negative": ["7", 0],
            "latent_image": ["5", 0]
        },
        "class_type": "KSampler"
    },
    "4": {
        "inputs": {
            "ckpt_name": "v1-5-pruned-emaonly.ckpt"
        },
        "class_type": "CheckpointLoaderSimple"
    },
    "5": {
        "inputs": {
            "width": 512,
            "height": 512,
            "batch_size": 1
        },
        "class_type": "EmptyLatentImage"
    },
    "6": {
        "inputs": {
            "text": "styled sports jersey pattern, tileable vector art",
            "clip": ["4", 1]
        },
        "class_type": "CLIPTextEncode"
    },
    "7": {
        "inputs": {
            "text": "blurry, low quality, photorealistic",
            "clip": ["4", 1]
        },
        "class_type": "CLIPTextEncode"
    },
    "8": {
        "inputs": {
            "samples": ["3", 0],
            "vae": ["4", 2]
        },
        "class_type": "VAEDecode"
    },
    "9": {
        "inputs": {
            "filename_prefix": "EA_Asset_Injest",
            "images": ["8", 0]
        },
        "class_type": "SaveImage"
    }
}

def queue_prompt(prompt):
    p = {"prompt": prompt}
    data = json.dumps(p).encode('utf-8')
    req = urllib.request.Request(f"http://{server_address}/prompt", data=data)
    response = urllib.request.urlopen(req)
    return json.loads(response.read().decode('utf-8'))

# Send prompt to headless ComfyUI server
response_data = queue_prompt(prompt_workflow)
print(f"Prompt queued successfully! ID: {response_data['prompt_id']}")
⚠️ Common Pitfall: How to Enable Dev Mode

By default, the ComfyUI web interface only exports standard visual workflows. To export the API JSON, you must open the ComfyUI settings (gear icon) and check "Enable Dev Mode Options". This adds a "Save (API Format)" button to the main toolbar.

Industrial Production Pipeline: Perforce & CI/CD Hooks

How does this play out in a real studio pipeline? Imagine a game team creating styled jerseys or custom logos for a sports game like EA Sports FC.

Instead of hiring an artist to manually run images through ComfyUI, the process is built directly into the version control pipeline:

┌─────────────────┐ Submit Texture ┌──────────────────┐ Trigger Workflow ┌─────────────────┐ │ Artist Workstation │─────────────────>│ Perforce Server │─────────────────>│ CI/CD Runner │ │ (Blender/Maya) │ │ (Depot / git) │ │ (Python Script) │ └─────────────────┘ └──────────────────┘ ────────┬─────────┘ │ Runs ▼ ┌─────────────────┐ Output Asset ┌──────────────────┐ Retrieve Outputs ┌─────────────────┐ │ Artist Workstation │<─────────────────│ Perforce Server │<─────────────────│ Headless GPU │ │ (Styled Jersey) │ (Auto-Submit) │ (Depot / git) │ │ (ComfyUI Node) │ └─────────────────┘ └──────────────────┘ └─────────────────┘

1. **Submit Draft**: An artist models a basic 3D jersey pattern and submits the flat texture blockout to Perforce.

2. **CI Trigger**: The Perforce commit trigger fires a Python script on a build runner machine equipped with a high-end GPU.

3. **Headless Execution**: The Python script parses the texture path, modifies the ComfyUI API JSON inputs to point to the submitted image, and posts the workflow to the headless ComfyUI server.

4. **Result Verification**: The server runs the diffusion model to stylize the texture, generates a preview, and automatically commits the processed, production-ready asset back to the Perforce depot under the target folder.

💚 Enterprise Scalability Tip

By shifting generation to a central headless GPU server, you eliminate the need to purchase expensive AI GPUs for every artist workstation. Artists can run basic textures on entry-level laptops, relying on the central build server to render high-fidelity variations overnight.

Key Takeaways

  • Headless ComfyUI runs without a visual browser window, executing node workflows completely via API calls and JSON dicts.
  • To generate API payloads, you must enable Dev Mode in the settings to export visual graphs into the execution-friendly API JSON.
  • Python scripts communicate with ComfyUI via HTTP POST to enqueue prompts and WebSockets to track sampler progress and return files.
  • Automated triggers can hook into version control systems (like Perforce or Git) to run assets through ComfyUI background servers upon check-in.
  • Centralizing ComfyUI runs on dedicated GPU farm nodes cuts hardware costs and keeps workflows consistent across the entire project.
